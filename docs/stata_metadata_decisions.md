# Stata metadata capsule decisions

Version 3.0.10 extends the version-1 capsule contract across Parquet files, directories, and globs.

- The footer key is `org.stata.pq.labels.v1`. Its JSON envelope is versioned and contains a zstd-compressed, base64-encoded, zero-observation `.dta` capsule plus an explicit Parquet-to-capsule column map.
- Polars `ParquetWriteOptions` remains the writer surface. Its batched writer inserts `ARROW:schema` alongside the custom key, so the new footer entry does not replace existing Arrow metadata.
- Stata creates and applies capsules. Rust only validates, compresses, embeds, extracts, and bounds them. Extracted content is opened with `use` in a temporary frame and is never passed to `do`, `run`, or another code-execution surface.
- Version 1 limits compressed capsules to 16 MiB, decompressed capsules to 64 MiB, JSON envelopes to 24 MiB, and Parquet footer metadata to 128 MiB. Future readers must retain bounded decompression even if those ceilings change.
- Exact physical names live in the envelope column map. In-memory transport names use the `_pq_parquet_name` variable characteristic; the older `{parquet_name:...}` variable-label marker is read only as a backward-compatible save fallback.
- Metadata writing is opt-in (`statametadata`) and restoration is automatic for a Parquet file, directory, or glob unless `nostatametadata` is specified. `label` and `statametadata` are mutually exclusive.
- Ordinary, partitioned, chunked, streamed, consolidated, partition-plus-chunk, and partition-plus-chunk-plus-stream saves are supported. `stream` and `consolidate` affect output only when `_N > chunk()`. An empty partitioned save and `statametadata partition_by() consolidate` return `r(198)` without changing output.
- The capsule carries variable labels, value labels, display formats, variable notes, the dataset label, and dataset notes. All of these already travel inside the zero-observation `.dta`, so no Rust or footer-format change is needed to add them. The dataset label is the one attribute Mata can neither read nor write, so it is captured and applied in ado; everything else moves through `st_varformat()` and `st_global("<var>[note#]")`. Note text is never placed in command-line position, so quotes, backticks, and dollar signs round-trip verbatim.
- Capsule membership is every saved variable, unconditionally, whenever `statametadata` is given. It is not conditioned on the data having labels, for two reasons. Display formats and storage types are metadata and every variable has both, so "this dataset has nothing to carry" is never true once they are in scope — an unlabelled `byte`/`int` dataset is precisely the case where the saved type matters most. And any trigger that consulted formats or types would not be storage-type independent: "default format" is defined relative to a storage type, and a relaxed schema can give one logical column different types in different fragments, so the trigger could fire for one fragment of a save and not another, leaving the fragments disagreeing. Omitting the option remains the way to get metadata-free Parquet.
- The dataset label is restored with `label data `"`macval(...)'"'`. Compound quotes alone are not enough: without `macval()` Stata rescans the substituted text, so a label containing `$name` is replaced by that global's value and a `` `...' `` sequence is dropped. Verified both directions.
- `cast()` exemption is per column, not global. Its JSON keys are physical Parquet column names, so a column renamed on import is matched through its `_pq_parquet_name` characteristic. `cast(string asis)` keeps the caller's compound-quote delimiters inside the macro value, so the payload is assigned bare before parsing — keeping them mis-pairs every quote in the JSON.
- A display format is applied only when the loaded column has the same string/numeric class as the saved column, so a read-time cast degrades to skipping the format rather than failing the restore. Restoring notes clears any notes already on the target first, so the result is the saved state rather than a merge.
- Storage types are restored by a post-load `recast`, not by declaring the saved type to the reader before the values are seen. The capsule records the type the data had at save time, but the file may since have been rewritten by another tool, widened by a `relaxed` multi-file union, or promoted by `safe_int64`; a type asserted ahead of the data would push out-of-range values into missing at `rc 0`. `recast` compares against the actual values and refuses when they would change, and a refusal leaves the wider loaded type, which holds every value exactly. The cost is transient memory: the column is read at the reader's type and narrowed afterwards.
- `recast` signals refusal by printing `N values would be changed; not changed` and still returns `rc 0`, so the restore confirms success by re-reading `st_vartype()` and never by the return code.
- `compress` and `compress_string_to_numeric` restate every column's type, so they suppress the recast wholesale; `cast()` names specific columns, so only those are exempted. Either way the rest of the capsule is still restored, and the restore never silently undoes what the caller asked for.
- Cross-fragment canonical comparison covers the column map, variable labels, and value-label definitions, but not formats or notes. Two fragments differing only in a format or a note therefore compare compatible, and a `nopartitionoverwrite` extension reuses the existing envelope. Closing that gap requires a Rust-side change to the canonical comparison.
- `pq use` restores dataset-level metadata; `pq append` restores variable metadata for newly created variables only and never overwrites the existing dataset label or dataset notes. Partition extension with `nopartitionoverwrite` validates every existing fragment and the proposed semantic identity before creating or replacing output; compatible extensions reuse the existing exact envelope.
- One sorted, deduplicated resolver supplies the physical `.parquet` files for read scans, footer preflight, partition extension, consolidation, and diagnostics. Empty matches and non-Parquet entries are rejected rather than guessed.
- Multi-file validation distinguishes all-absent metadata from valid present metadata and errors on mixed, malformed, oversized, unsupported, or semantically conflicting footers. Exact envelope equality is the fast path; otherwise canonical comparison includes the physical/capsule column map, variable labels, exact value-label names, all mappings (including unused codes and extended missings), and definition sharing while ignoring non-semantic `.dta` header details.
- `pq use` validates before describe can scan data, maps the agreed capsule after describe establishes final Stata names, and applies it once only after all selected data load successfully. Projection, `drop()`, long physical names, filters, row ranges, sampling, casts, compression, and relaxed schema union do not weaken metadata identity.
- `nostatametadata` skips both validation and restoration but uses the same data scan. `pq append` validates the selected footer set but does not apply its capsule to existing Stata variables. `pq merge` explicitly uses the data-only path.
- Consolidation validates inputs before collecting them, writes a unique same-parent staging file with the agreed Stata key and a regenerated `ARROW:schema`, validates the completed footer, then swaps it into place. A failed install rename restores the original fragment directory.
