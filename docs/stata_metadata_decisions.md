# Stata metadata capsule decisions

Version 3.0.10 extends the version-1 capsule contract across Parquet files, directories, and globs.

- The footer key is `org.stata.pq.labels.v1`. Its JSON envelope is versioned and contains a zstd-compressed, base64-encoded, zero-observation `.dta` capsule plus an explicit Parquet-to-capsule column map.
- Polars `ParquetWriteOptions` remains the writer surface. Its batched writer inserts `ARROW:schema` alongside the custom key, so the new footer entry does not replace existing Arrow metadata.
- Stata creates and applies capsules. Rust only validates, compresses, embeds, extracts, and bounds them. Extracted content is opened with `use` in a temporary frame and is never passed to `do`, `run`, or another code-execution surface.
- Version 1 limits compressed capsules to 16 MiB, decompressed capsules to 64 MiB, JSON envelopes to 24 MiB, and Parquet footer metadata to 128 MiB. Future readers must retain bounded decompression even if those ceilings change.
- Exact physical names live in the envelope column map. In-memory transport names use the `_pq_parquet_name` variable characteristic; the older `{parquet_name:...}` variable-label marker is read only as a backward-compatible save fallback.
- Metadata writing is opt-in (`statametadata`) and restoration is automatic for a Parquet file, directory, or glob unless `nostatametadata` is specified. `label` and `statametadata` are mutually exclusive.
- Ordinary, partitioned, chunked, streamed, consolidated, partition-plus-chunk, and partition-plus-chunk-plus-stream saves are supported. `stream` and `consolidate` affect output only when `_N > chunk()`. An empty partitioned save and `statametadata partition_by() consolidate` return `r(198)` without changing output.
- When selected variables have variable or value labels, every fragment from one save receives the same deterministic envelope. With no label state, `statametadata` writes ordinary metadata-free fragments. Partition extension with `nopartitionoverwrite` validates every existing fragment and the proposed semantic identity before creating or replacing output; compatible extensions reuse the existing exact envelope.
- One sorted, deduplicated resolver supplies the physical `.parquet` files for read scans, footer preflight, partition extension, consolidation, and diagnostics. Empty matches and non-Parquet entries are rejected rather than guessed.
- Multi-file validation distinguishes all-absent metadata from valid present metadata and errors on mixed, malformed, oversized, unsupported, or semantically conflicting footers. Exact envelope equality is the fast path; otherwise canonical comparison includes the physical/capsule column map, variable labels, exact value-label names, all mappings (including unused codes and extended missings), and definition sharing while ignoring non-semantic `.dta` header details.
- `pq use` validates before describe can scan data, maps the agreed capsule after describe establishes final Stata names, and applies it once only after all selected data load successfully. Projection, `drop()`, long physical names, filters, row ranges, sampling, casts, compression, and relaxed schema union do not weaken metadata identity.
- `nostatametadata` skips both validation and restoration but uses the same data scan. `pq append` validates the selected footer set but does not apply its capsule to existing Stata variables. `pq merge` explicitly uses the data-only path.
- Consolidation validates inputs before collecting them, writes a unique same-parent staging file with the agreed Stata key and a regenerated `ARROW:schema`, validates the completed footer, then swaps it into place. A failed install rename restores the original fragment directory.
